# Orval migration contracts

The application pins `orval@8.46.0` for type generation and retains its existing
HTTP client, authentication, CSRF, epoch checks and request serialization.

```sh
npm --prefix web ci
npm --prefix web run generate:api
npm --prefix web run test:api
git diff --exit-code -- api/openapi.json web/src/api/schema.d.ts web/src/api/generated
test -z "$(git ls-files --others --exclude-standard -- api/openapi.json web/src/api/schema.d.ts web/src/api/generated)"
```

`generate:api` runs one schemas-only Orval CLI process, generates compatibility
declarations and canonicalizes the model file's final newline. Use the complete
command: standalone Orval `--outdated` does not cover the bridge or normalization.
`test:api` generates synthetic fixtures in **separate CLI processes**, checks
TypeScript contracts and tests the closed-empty request guard. Scratch outputs
under `.local/orval` are ignored.

## Frozen baseline

`baseline/schema.d.ts` preserves all 47 former component models and seven query
contracts from commit `f2006be6da67e2eb264ec1d904631abc4cc3e2d9`, generated by
openapi-typescript 7.13.0. Unused paths/response/header contracts were omitted.
`baseline/fixtures.d.ts` was generated by that version from `contract.openapi.json`.
The retired generator is not installed or executed by these tests.

The checker uses strict/exactOptionalPropertyTypes to compare model assignability
in both directions, model keys and every query contract. Synthetic fixtures cover
nullable/optional/enum/oneOf/anyOf/allOf, date/int64 options and invalid assignments.
The app's model output must contain no executable declarations. Intentional API
changes require reviewing and updating the baseline fixtures; do not refresh them
merely to silence failed assertions.

## Compatibility boundary and upstream defects

The bridge supplies `components.schemas` and `operations[id].parameters.query`.
It does not recreate the old generator's complete paths/response/header/requestBody
API. New names and unsupported parameter structures require review.

Orval 8.46.0 widens `Settings-smtp-testRequest` from a closed empty object to an
open dictionary. The bridge maps only that model to `Record<string, never>` after
checking its exact closed-empty schema. Schema growth fails generation and is
covered by a regression test. App consumers must use the compatibility boundary:
the raw Orval model retains this defect. The existing `smtpTest(key, signal)` sends
`{}` and the server rejects client-selected recipients with 422.

Schemas-only outputs in one Node process can share model-resolution results when
their date/bigint options differ. Reordering, copying input objects/spec files or
sequential generate() calls in the same process do not solve it. A fresh CLI
process per project does. The app has one project; test:api isolates both variants.
Dates/int64 remain strings/numbers in the app. Date/bigint fixtures test type
generation and do not alter application JSON parsing or stringification.

## Sources and security

- [Maintenance termination](https://github.com/openapi-ts/openapi-typescript/issues/2874)
- [Pinned release](https://github.com/orval-labs/orval/releases/tag/v8.46.0)
- [Output options](https://orval.dev/docs/reference/configuration/output/)
- [External reference controls](https://orval.dev/docs/reference/configuration/input/#externalrefs)
- [Pinned resolver source](https://github.com/orval-labs/orval/blob/v8.46.0/packages/core/src/resolvers/object.ts)

The application reads only its Go-generated local spec and disables external refs.
The pinned version follows fixes for
[core enum injection](https://github.com/orval-labs/orval/security/advisories/GHSA-v36f-hqj9-q8rr),
[array const injection](https://github.com/orval-labs/orval/security/advisories/GHSA-x4fj-j9hr-ccr6),
[composed type injection](https://github.com/orval-labs/orval/security/advisories/GHSA-6h9g-hcv4-66p6) and
[effect enum injection](https://github.com/orval-labs/orval/security/advisories/GHSA-f96w-763g-hg7v).
Audit the complete lock graph on generator updates. It now has 236 dependency
entries versus 159 previously; production dependencies and client runtime code
are unchanged.
